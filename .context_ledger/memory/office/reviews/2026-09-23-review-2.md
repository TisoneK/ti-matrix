# The app UI, rebuilt from the ground up

**2026-09-23 · Nadia (S003) · branch `app-ui-rebuild`**

## What happened

The renderer was thrown away and rebuilt. Not restyled — the layout, the components, the stylesheet and
the data layer are new, and the old ones are deleted. The window is now a **run inspector**: the map a run
fills in as it observes, the search tree it grew, and a ledger of every decision with the belief behind it
and the world's answer underneath. Config — endpoint, model, key, seed — moved behind one toggle, because
it is the ship's instrument panel and not the ship.

Two things the old renderer could not do at all are now the point of the new one. A run **plays back**:
one cursor over the run's decisions, and a scrubber, play/step, speed and bookmarks that rebuild the map
and the tree at that moment rather than replaying a recording. And two runs can be **compared**: the same
seed against two models, under one cursor, with both trails drawn on one grid when they read the same
world — which is the only way to see where two agents actually diverged.

## How it is put together

The whole design is one idea: a run is an event log, a cursor is a decision index, and every panel is a
pure function of the two (`app/renderer/core/project.ts`). Playback is free because dragging the scrubber
back re-derives belief instead of recording it; comparison is the same function called twice.

```
events ─┬─► decisions (the ledger: one row per turn of the search loop)
        ├─► knowledge (the map, as it stood at the cursor)
        ├─► tree      (the search, as it stood at the cursor)
        └─► trust     (the confidence curve, up to the cursor)
```

Four folds under `core/`, none of them React, all of them tested. The panels are drawings; the folds are
where the thinking is.

The maze map was the interesting problem. The engine never shows a run its maze (deliberately —
`ti_matrix/adapters/maze.py` says so), so the map is reconstructed from the world's own sentences: *"cell
1,1 — open: south, east · THIS IS THE EXIT"*, *"a wall blocks north from 1,1"*. It was already being done
in the old renderer; the rebuild adds the parts that make it readable — cells coloured by how often the
run stepped on them (loops light up immediately), a ghost trail of cells it walked into and left, and the
live branch drawn only where the state is still standing.

## What was found and fixed

Every one of these was found by running the thing, not by reading it. The most useful were the layout
bugs, because they were invisible in the code and obvious in a screenshot.

| # | Finding | Severity |
|---|---|---|
| 1 | `MapPanel` and `LibraryPanel` returned their parts as siblings, so `.stage`'s grid laid them out as separate **cells of the page** instead of one pane. The map drew itself over the search tree. | High |
| 2 | The app shell used a fixed four-row grid while the compare and library views render two children — the stage collapsed to 213px and the maps had zero height. Now a flex column, which cannot depend on which surfaces are present. | High |
| 3 | Field labels were not associated with their inputs, and wrapping the hint inside the label made the accessible name *"Model the name the endpoint knows it by"*. Now `for`/`id` with the hint as a `description`. | High (a11y) |
| 4 | Every ledger row's bookmark button was named "bookmark this step" — six identical controls for a screen reader. Now named by step. | Medium (a11y) |
| 5 | The map's absolute-positioned legend collapsed to min-content (one visible item). Replaced with a static footer row, which also stops it covering the map. | Medium |
| 6 | After a finished run, rewinding left no way back to the end — "jump to live" only existed while a run was streaming. | Medium |
| 7 | An inferred wall ("this cell listed its openings and this was not one") could erase a corridor another observation had established. The world is allowed to contradict itself; the precedence is now explicit — an inference never overrides a corridor, a refusal always does. | Medium |
| 8 | `done` decisions lost the evaluator's score and the world's evidence, so the row that settles a run showed neither. | Low |
| 9 | The header readout labelled "progress" was showing the last decision's *confidence*. Different things: how far the run came, versus how good the move looked. | Low |
| 10 | A 127ms run displayed as "0s". | Low |
| 11 | `.map-toggles` and a duplicated blocked-reason in the config drawer: dead code and noise. | Low |

The tree fold was rewritten mid-session on discovering — from a real run's frames, not from the source —
that the engine stamps its own tree ids (`state` carries `node` and `parent`, every other event carries
`at`). It had been deriving the shape from trails, which is a worse guess at something the engine had
already said. Trail-derivation is kept as the fallback for logs that predate the ids.

## What is verified

- `npm run typecheck` (both tsconfigs), `npm run test` (**129 assertions**: the folds against hand-built
  runs, plus the four world parsers against the exact strings the adapters write), `npm run build`.
- The **engine's suite** 207 passed and the **sidecar's suite** 34 passed — untouched by this work.
- A **real run** driven end to end in a browser against the real sidecar and a scripted
  OpenAI-compatible endpoint: 102 events, 14 decisions, 6 retreats; the map parsed the real observation
  strings (grid 11×9, 39 floors, 16 cells walked, coverage 41%), the tree read the engine's own ids (8
  states, 7 branches under the root, all abandoned but the last), and the ledger flagged each turn.
- Scrubbing to step 3 of 6 rebuilt the map and the tree at that cursor (3 nodes, not 4; 3 rows marked as
  future); bookmarks saved and reloaded; the library listed and sorted saved runs; compare mode overlaid
  two runs of the same world; the non-maze world surface rendered populated cards from the parsers.

## Open items and the one regression to know about

The three prose worlds (files, ledger, browser) keep their parsers and now have a real surface — cards of
what the run read, from the same parsers the tests cover — but it is **thinner than the views they had
before**: the old renderer had a directory tree view, a vault report view and a page view. Their parsers
are intact and tested, so the gap is presentation only; it is logged as a backlog row rather than
disguised. The maze is where the product's question is sharpest, and it is where the rebuild went.

Also open, and recorded: the window has only ever been driven in a browser harness with the preload
stubbed (no display was available for a real Electron window in this session); the library's IPC was
exercised through that harness's own filesystem, not through Electron's `userData` path; nothing has been
packaged, signed or updated; and the stub model used for testing lives outside the repo, so a real
end-to-end run against a real LLM is still unverified.

## Follow-up, same session: the title bar, and a bug the harness had hidden

Asked for a custom title bar. The rail **is** the title bar now: it already carried what one carries (the
name, the state, the way in), so OS chrome above it was spending a strip of screen for nothing. macOS keeps
its traffic lights, inset over the rail, and the rail leaves them their corner; everywhere else the frame
is gone and the rail draws minimize/maximize/close over new `tm:window-*` channels, with the maximize state
pushed from main so the middle button knows what it means. The rail takes the drag region and everything
clickable inside it opts out; a double-click on its empty space maximizes, which a custom title bar has to
add back because the OS no longer does it.

Launching the real window to check it found the session's most serious bug — and one this review had
already gotten wrong. **The session library's IPC handlers were written but never registered**, so every
`tm:runs-list` / `tm:run-save` call from the renderer failed with *"No handler registered"*. The browser
harness that verified everything above had stubbed `window.tm`, so the library appeared to work while the
real app could not save or list a single run. The claim above that "the library listed and sorted saved
runs" was true of the harness, not of the app.

Verified in the real window this time: the renderer receives the platform and the window channels, the rail
reports `-webkit-app-region: drag` with `no-drag` on its controls, and `toggleMaximize` → `state()` →
`toggleMaximize` round-trips `false → true → false` through the main process. The controls themselves were
screenshotted with the platform patched, since this machine cannot be a Windows box.

The lesson is worth keeping: **a stubbed boundary hides exactly the bugs that live at the boundary.**
`B-2026-09-23-1` is closed by this. What remains open: no run has been watched against a real LLM, and the
prose worlds' panels are still thinner than the views they replaced (`B-2026-09-23-2`, `B-2026-09-23-3`).
