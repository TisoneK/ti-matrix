# 2026-09-26 — the UI pass: what "built by a backend developer" actually was

Session 8, Rosalind (S008), deepseek-flash. The supervisor's report was that the app "feels like it
was developed by a backend developer not a real designer", scoped to the whole UI in an earlier
session. This is what I found looking at the running window, what I changed, and what I deliberately
left.

## The verdict, in one line

The design system was fine; the composition was not. That distinction is the whole report.

`styles.css` opens with a documented visual grammar — ice means live, amber means belief, red means the
world pushed back, green means the world agreed; serif for a section's own name, mono for everything
the engine said; "an instrument's grammar, not a dashboard's". The welcome screen and the config drawer
are genuinely well-composed, and the library and the map's colour semantics are deliberate. What read as
backend-built was the *layout* of the run view: panes with no focal point, a stat block doing the work of
a sentence, meaning carried by unlabelled glyphs, and controls duplicated because nobody had looked at
the whole strip at once. Every one of those is a composition defect, and none of them needed the palette
or the flag vocabulary to change.

## The audit

Done by driving a real window, not by reading source: a second Electron instance on its own
`--remote-debugging-port` and its own `--user-data-dir`, so the supervisor's open window and its sidecar
were never restarted or touched. Screenshots at 1440, 1280, 1024 and 820; a maze run and a files run;
the config drawer, the library, and a saved run reopened from it.

## Fixed

1. **A stopped run's synthesized answer was dropped on the floor** (High, product bug). `partial_answer`
   rides on the event that ends a run, and there are two shapes of ending: with no fan in front of it,
   or — far more often — at the end of an iteration that folded a last move first. Only the first shape
   read the field, and it read it into `evidence`, which everywhere else on a decision means the world's
   own words. So the common case showed the chosen reading's excerpt in place of the answer. The answer
   now has its own pair of fields, captured on both paths. This arrived as uncommitted, red work in the
   working tree with no claim and no commit naming it; I carried the intent forward and fixed it.
2. **The scrubber's marks all said "confirmed"** (Medium). A mark's colour came from `flags[0]`, and
   `flags[0]` is `confirmed` on nearly every row — so a timeline built to show you where the run got
   brave drew thirty identical green ticks. The ledger's rows already had the right rule; the scrubber
   had a second, wrong copy of it. Now one function, both callers, four assertions.
3. **The transport contradicted itself at the end of a finished run** (Low). "Rewound to 35" beside a
   "jump to end" button that went where the cursor already was.
4. **Empty panes were voids** (High, first impression). Three grey whispers centred in three to six
   hundred pixels of nothing. Now a dashed plate with a label in the pane's own voice.
5. **The map's footer was a data dump** (High). Five 9.5px caps labels wrapping raggedly under a two-line
   instruction, with the run's last reading clipped into the narrowest third. Now three divided zones,
   coverage on one line, the reading given room. Two of the five numbers left the strip because the pane
   head and the transport already show them.
6. **No type above 13.5px in the run view** (Medium). All hierarchy was carried by colour. Three steps
   above body now.
7. **The command bar clipped a world description mid-word** (Medium) — and the reason a disabled Run
   could not be pressed lived in a `title` attribute, which Chromium never fires on a disabled control,
   so it was on screen nowhere. The note is gone from the bar (the picker's tooltip and the setup sheet
   carry it whole); the slot now belongs to the blocked reason, in amber, at reading size.
8. **Compare's empty state hid its own buttons** (Medium). A 100%-tall plate inside a clipping body
   pushed the two "choose a run" buttons — the only way to act on that screen — out of sight.
9. The files world drew three cards saying nothing where one sentence belongs; the search tree's head
   wrapped its button onto a ragged second line.

## Still open — and one of these is worse than anything I fixed

- **The files world can declare a *verified* answer that is unrelated to the question** (High, not a UI
  defect — I did not touch it). The rule-based reasoner settles `done` when it reads a file whose *path*
  contains any word of the goal. A saved run in the library answers "how many python files are in the
  `ti_matrix` package directory, and what does it do?" with the first 200 characters of
  `app/package-lock.json` — because the goal contains the word "package". The window paints it green and
  labels it "Answer", which is the app doing exactly what it was told: a settled `done` is world-verified.
  The defect is upstream of the paint: path-word overlap is too loose a test for "the file the goal
  named". Filed as a backlog row with the evidence.
- **The library's identity/metrics split is still nine columns at one weight** (Low). I added a hairline
  between the groups, which helps; the deeper question — whether always-zero metrics belong in a table
  whose point is comparison — is a product decision, not a styling one.
- **The rail says "BELIEF 48%" next to "PROGRESS 100% · settled"** (Low). Two confidence words on one
  line, one of them naming a quantity a person would have to read the source to interpret.
- The browser world's screenshot panel (a known backlog item) would land in the world surface, which I
  restructured; whoever builds it should know the answer card now owns the top of that pane.

## Verification

`ledger-gates run pre-commit`, `integration` (344 tests) and `exit` all pass, including the production
build. Every visual change was re-checked in the running window rather than assumed, at four widths.
