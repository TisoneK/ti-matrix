# 2026-09-27 — files adapter walk redesign (Greer, S013)

## What happened

The supervisor ran the same "locate the repo" goal on TiMatrix and on a sibling
project (LocalMind, a separate repo on this machine) and TiMatrix lost badly:
79s / 20K tokens for a bare path, against LocalMind's 9.5s / 5.6K tokens with a
richer answer. Both runs used real models — this was not a model-quality gap.

## What was found

Reading LocalMind's `backend/src/tools/system_search.py` (not a dependency of
this repo — read for comparison only) against `ti_matrix/adapters/files.py`'s
`find_files` side by side:

- `find_files` walked straight into `node_modules`, `.git`, `.venv` on every
  call. The existing noise filter (`FilesReasoner.is_noise`, in `builtin.py`)
  only ran *after* a full walk, over results already paid for — it protected
  the rule-based reasoner's answer quality, never the walk's own cost, and did
  nothing at all for an LLM-driven run (which is what the compared run used).
- The walk's only bound was an entry count (20,000). No wall-clock ceiling, so
  one slow-to-stat subtree could burn real time without ever tripping the count.
- Symlinks were never skipped — a real (if unexercised) cycle risk.
- `README.md` claimed `--model builtin` doesn't work in the shell CLIs yet.
  Checked against `ti_matrix/adapters/session.py::Seats.seats()`: it has, since
  `151606e` (2026-09-25) — the README note was written the day before that fix
  landed and never updated.

## What changed

- `_NOISE`, `is_noise`, `_GENERATED_BASENAMES`/`_GENERATED_SUFFIXES`,
  `is_generated_artifact` moved from `builtin.py` into `files.py` — one
  definition instead of two independently-maintained copies.
- `_find_files` now skips a noise-named entry (and never queues it for
  descent) the instant it's seen, instead of filtering matches after the walk
  finished.
- Added `_WALK_MAX_MS` (2500ms default), checked alongside the existing
  entry-count cap; both report through the same "stopped at/after ... — more
  may exist unseen" sentence the entry cap already used.
- Symlinks are now skipped rather than followed.
- README's stale "CLIs still require an endpoint" note replaced with a working
  example (verified live, not just written).

Full rationale: `.context_ledger/memory/office/plans/decisions.md` → ADR-6.
Commit: `0d28926`.

## Verified

- `pytest tests` — 331 passed (3 new: noise-dir pruning, symlink skip, the new
  time bound), up from the 328-test baseline.
- Pre-commit gate green: server tests, app typecheck, app test suite.
- Live run, not just the suite: `python -m ti_matrix.adapters.files_cli --model
  builtin --root ~ "locate the ti-matrix repo"` against this machine's real
  home directory. The new "stopped after 2500ms" message fired exactly as
  designed on both `find_files` calls the reasoner made.

## What's still open

That live verification run surfaced a **separate, pre-existing bug**, not
fixed in this session: `FilesReasoner.evaluate()` settled `done=True,
progress=1.0` on `/Users/bao/.agent-browser/ti-matrix-a11y.config` — a
browser-automation cache file whose name merely contains the substring
"ti-matrix" — while the real checkout was sitting right there among
`find_files`'s 443 hits, never looked at. The grounding check (`files.py`'s
`named = any(w in basename for w in words) and not is_generated_artifact(path)`)
has no concept of "this file's directory has nothing to do with the goal."
This is an answer-quality/judgment call, not a walk-performance bound, and
fixing it in the same change as the walk redesign would have mixed two
different concerns — filed as `B-2026-09-27-1` with full repro instead.

Also parked, not started (`P-2026-09-27-1`): LocalMind's multi-token/glob
matching, its relaxed-fallback retry, and its multi-operation tool shape
(`recent`/`largest`/`duplicates`/`apps`/`open_with`) — each a real feature
needing its own design, not a bound that was simply missing.
